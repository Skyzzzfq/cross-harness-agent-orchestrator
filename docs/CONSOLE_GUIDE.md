# 控制台傻瓜教程（5 分钟第一次跑通）

> 写给"不想看说明书、只想点鼠标"的人。跟着做，每一步都告诉你**点哪里、看到什么算对**。  
> 全程不需要碰命令行。想真正让它帮你改代码（写任务）的人，看文末第 6 节。

---

## 0. 启动控制台（第一次）

1. 打开文件夹 `D:\workspace\connect`，**双击 `start.cmd`**。
2. 会弹出一个黑色终端窗口（写着 `console listening on http://127.0.0.1:端口`），几秒后浏览器自动打开控制台页面（深色界面，左上角写着 **Agent Hub 编排控制台**）。
3. **认准地址**：如果浏览器没弹出来，就手动打开黑色窗口里写的那个地址。地址端口可能是 8080，也可能因为被别的软件占用而变成 8081、8082……
   - ⚠️ 如果你打开看到的是 **"Steam / Inspectable Web Contents / 欢迎来到 Steam"**：那不是我们，是 Steam 抢了端口。关掉那个标签页，改开黑色窗口里写的那行地址。
4. 页面顶部有四个标签：**运行管理 / Agent 对话 / Agent 团队 / 厂商连接**。

在 **Agent 对话** 左栏可以保存项目元数据：填写项目名称、本地绝对工作空间和默认团队后点「保存项目」。路径会由服务端验证，保存/删除只改 `.agent-hub/settings.json`，不会删除你的代码。当前控制台根目录不会在浏览器内热切换；要真正切换工作空间，请从目标目录重新双击 `start.cmd` 启动。

## 1. 先看一眼：厂商登录了没

点顶部 **「厂商连接」**，你会看到两张卡片：

| 卡片        | 你想看到的               | 如果没看到                                                                  |
| --------- | ------------------- | ---------------------------------------------------------------------- |
| Codex     | 绿色「CLI 可用」+ 紫色「已登录」 | 点卡片上的蓝色 **「一键登录授权」** 按钮，浏览器会弹出授权页（或按弹出的登录窗口提示操作），完成后点页面右上角 **「重新探测」** |
| CodeBuddy | 绿色「CLI 可用」+ 紫色「已登录」 | 点卡片上的蓝色 **「一键登录授权」** 按钮 → 浏览器会在后台自动打开中国站授权页 → 完成授权后回本页点 **「重新探测」** |

> 不用再自己开 PowerShell，也不需要输入 `/login`。「一键登录授权」会在后台启动 CodeBuddy SDK 认证流程，自动打开中国站授权页并等待回调。这里的项目目录只决定本次后台认证使用的项目环境；登录授权仍保存在 Windows 用户级目录，同一用户下更换项目不需要重复登录。
>
> 首次登录只需要做这一次。两个都「已登录」后，进入下一步。

## 2. 建一个 Run，并启动调度

1. 点顶部 **「运行管理」**。
2. 找到 **「新建 Run」** 卡片，保持「主管计划：自动协作（推荐）」并点蓝色按钮 **「创建 Run」**（Run 标识可以留空，会自动生成一个）。如果希望先人工检查主管的计划，再选择「生成后人工批准」。
3. 稍等 1~2 秒，下面列表出现一张 Run 卡片，右上角状态是灰色的 **「serve 未启动」**。
4. 点这张卡片上的 **「启动 serve」** 按钮。Run 会直接使用创建时选择的团队，不再要求你重新输入配置文件路径。
5. 卡片右上角变成绿色闪烁的 **「serve 运行中」**。✅ 调度已经开了，它会自动接任务、派给 AI 干。

> 「serve」就是这个项目的"调度器"：一直盯着数据库，有活就派给工人。运行中才能干活。

> **模型来源怎么选？** CodeBuddy 的「提供方」下拉框会把 **内置模型（CodeBuddy 默认）** 与 **自定义模型提供方** 分开；选择火山 CodingPlan 等自定义提供方后，下面的模型列表只显示该提供方的模型，不会和 CodeBuddy 内置模型混在一起。



---

## 3. 发第一个任务（推荐交给团队主管）

1. 点 Run 卡片上的 **「详情」**，会展开一个面板。
2. 点展开面板里最上面那排的 **「＋ 发起任务」**。
3. 弹出一个输入框（"任务说明"），**粘贴下面这句话**再点确定：
   ```
   请让两个 Worker 分别用一句话介绍自己，最后由你汇总两个回答并告诉我。
   ```
4. 默认的 **「交给团队主管」** 会把这一句自然语言先发给当前 Run 的 Supervisor；主管再按团队配置给 Worker 分派子任务。只有需要绕过主管时才选「直接执行 Worker」。后端、提供方和模型默认从团队池读取，临时覆盖放在「高级覆盖」里。
5. 弹出绿色提示"任务已发起"后，点面板里的 **「刷新」**，看到表格里出现一行 `task-xxxx`。

---

## 4. 看它干完活

什么都不用做，盯着面板，大约 10~60 秒：

1. 任务那行的状态会变：紫色「就绪」→ 绿色「运行中」→ 蓝色「待审核」或绿色「已完成」。
2. 待审核任务先点 **「对话」** 查看完整任务说明和 Agent 返回，再点 **「通过」** 或 **「打回」**。serve 正在运行时也可以直接审核。
3. 顶部 **「Agent 对话」** 页面会按「项目 → 角色 → Agent → 任务」保留上下文，并自动刷新主管和每个 Worker 的调用状态和输出；对话内容以自然语言显示，内部计划 JSON 不会直接展示给你。
4. 往下滚，在 **「事件时间线（最近 40）」** 里能看到每一步发生了什么（派给谁、在跑、完成……），越靠上越新。
5. 想让它干多个活就多「发起任务」几次，调度器会自动分给空闲的 AI，表格里能同时看到好几个在跑。
6. 想立刻知道有没有新变化：点「刷新」，或者干脆等 8 秒（页面会自动刷新列表，不会把已经展开的详情收起或闪回）。

当两个 Worker 都完成后，调度器会自动创建一个主管汇总任务；你可以在任务列表或「Agent 对话」里看到最终的自然语言汇总。

在 **Agent 对话** 左栏可按「项目 → 角色 → Agent」筛选上下文。选择具体 Agent 后，页面只显示它关联的任务和后端调用；底部「运行中引导」会把补充说明先放入 durable 队列，页面会显示排队结果。CodeBuddy 是否能在当前 turn 立即插话取决于已验证的后端能力，不支持时由调度器在本轮结束后投递。

> 第一次跑通到这里就成功了。**你已经在用 Codex/CodeBuddy 当"外包团队"了。**

## 5. 控制按钮（每个都是字面意思）

展开 Run 详情后，面板顶部那排按钮：

| 按钮             | 作用             | 什么时候用   |
| -------------- | -------------- | ------- |
| ＋ 发起任务         | 派新活            | 想让它做事   |
| 暂停调度           | 暂时不派新活（在跑的不打断） | 想歇会儿    |
| 恢复调度           | 重新开始派活         | 暂停之后    |
| 刷新             | 手动看最新状态        | 等不及自动刷新 |
| 停止 serve（在卡片上） | 关掉调度器          | 今天不用了   |
| 收起 / 详情      | 展开或收起 Run 详情  | 管理多个 Run 时保持列表清爽 |
| 删除 Run         | 删除该 Run 的受管 worktree/运行目录并从列表移除 | 确认不再需要此 Run |

另外任务表格每行最右有 **「取消」** 和 **「删除」** 按钮：运行中的任务先取消；非运行任务可以删除。删除会清理任务记录，但保留 `task.deleted` 事件审计。

**收工**：点卡片上红色的 **「停止 serve」**，再关掉黑色终端窗口即可。数据都存在本地数据库里，下次启动还能看到这个 Run 的历史。

**删除 Run**：必须先停止 serve，点击「删除 Run」后确认。系统只删除 `.agent-hub/worktrees/<run-id>`、`.agent-hub/runs/<run-id>` 等受管目录，不会删除项目主目录；审计事件仍保存在本地数据库中。

---

## 6. 写任务与审核

写任务会在 Run 下创建受管 worktree，并要求填写允许修改的相对路径，例如 `src/a.py,tests/test_a.py`。Agent 完成后会停在 **「待审核」**：

1. 点 **「对话」** 阅读任务说明和实际返回；
2. 确认无误点 **「通过」**，系统提交并合并受控范围内的改动；
3. 需要返工点 **「打回」**，任务会重新回到就绪队列；
4. 运行中的任务不能删除，必须先取消并等待状态稳定。

## FAQ：卡住了看这里

**Q：浏览器打开是 Steam 页面？**  
A：Steam 占了 8080。用黑色终端窗口里 `console listening on` 那行的地址访问；`start.cmd` 每次会自动挑空闲端口。

**Q：任务一直停在「就绪 / 待审核」不动？**  
A：90% 是「serve 未启动」（看卡片右上角是不是灰的，先点「启动 serve」）；10% 是相关厂商没登录（去「厂商连接」看）。

**Q：点通过提示 controller 被占用？**
A：新版审核会复用正在运行的 serve 租约；如果仍提示占用，先点「刷新」确认控制台已加载新版页面，再重试。

**Q：任务变成红色「失败」/「阻塞」？**  
A：最常见的两种：① 该后端没登录（去厂商连接确认）；② 只读任务别担心，多半是 AI 网络/超时，点「取消」后再发一次。想看具体原因，去事件时间线找 `task.failed` 那行，后面的文字会说明。

**Q：CodeBuddy 老提示没登录但明明登录过？**  
A：连接页的登录态探测只读 Windows 用户级认证目录，不会为了刷新页面发送模型请求。若当前控制台是从受限环境启动，卡片会显示“无权读取”，这不等于未登录；请从桌面正常权限运行 `start.cmd` 后重新探测。模型下拉的自动测试或真实任务若能收到 CodeBuddy 回复，就已经证明当前模型请求可用，无需重复授权。

**Q：电脑重启后任务要怎么继续？**
A：先运行 `recovery-check --run <run-id>` 查看活动任务、过期租约和未确认调用，再运行 `reconcile --run <run-id>` 回收已经过期的尝试。若数据库损坏，先用 `db-backup` 留存当前文件，再用 `db-restore` 恢复备份，最后用 `db-verify` 检查完整性。`history-preview` 只提供清理预览，不会自动删除历史证据。
