# 控制台傻瓜教程（5 分钟第一次跑通）

> 写给"不想看说明书、只想点鼠标"的人。跟着做，每一步都告诉你**点哪里、看到什么算对**。
> 全程不需要碰命令行。想真正让它帮你改代码（写任务）的人，看文末第 6 节。

---

## 0. 启动控制台（第一次）

1. 打开文件夹 `D:\workspace\connect`，**双击 `start.cmd`**。
2. 会弹出一个黑色终端窗口（写着 `console listening on http://127.0.0.1:端口`），几秒后浏览器自动打开控制台页面（深色界面，左上角写着 **Agent Hub 编排控制台**）。
3. **认准地址**：如果浏览器没弹出来，就手动打开黑色窗口里写的那个地址。地址端口可能是 8080，也可能因为被别的软件占用而变成 8081、8082……
   - ⚠️ 如果你打开看到的是 **"Steam / Inspectable Web Contents / 欢迎来到 Steam"**：那不是我们，是 Steam 抢了端口。关掉那个标签页，改开黑色窗口里写的那行地址。
4. 页面顶部有三个标签：**运行管理 / Agent 团队 / 厂商连接**。

---

## 1. 先看一眼：厂商登录了没

点顶部 **「厂商连接」**，你会看到两张卡片：

| 卡片 | 你想看到的 | 如果没看到 |
|---|---|---|
| Codex | 绿色「CLI 可用」+ 紫色「已登录」 | 打开 PowerShell，`cd D:\workspace\connect`，执行 `codex login`，浏览器授权后回到本页点刷新 |
| CodeBuddy | 绿色「CLI 可用」+ 紫色「已登录」 | 打开 PowerShell：`cd D:\workspace\connect`，然后照下面三行做，授权完关掉窗口回来刷新 |

```powershell
$env:CODEBUDDY_INTERNET_ENVIRONMENT = "internal"
$env:CODEBUDDY_SKIP_GIT_BASH_CHECK = "1"
.\.agent-hub\tools\node_modules\.bin\codebuddy.cmd
```

（进入后输入 `/login`，会自动弹浏览器授权。卡片里那个灰框写的就是这些步骤，照着做即可。）

> 首次登录只需要做这一次。两个都「已登录」后，进入下一步。

---

## 2. 建一个 Run，并启动调度

1. 点顶部 **「运行管理」**。
2. 找到 **「新建 Run」** 卡片，点蓝色按钮 **「创建 Run」**（Run 标识可以留空，会自动生成一个）。
3. 稍等 1~2 秒，下面列表出现一张 Run 卡片，右上角状态是灰色的 **「serve 未启动」**。
4. 点这张卡片上的 **「启动 serve」** 按钮。
5. 浏览器弹出一个输入框问"团队配置文件路径"——**直接回车用默认**（`config/team.yaml`，即 1 个 Codex 主管 + 2 个 CodeBuddy 工人）。
6. 卡片右上角变成绿色闪烁的 **「serve 运行中」**。✅ 调度已经开了，它会自动接任务、派给 AI 干。

> 「serve」就是这个项目的"调度器"：一直盯着数据库，有活就派给工人。运行中才能干活。

---

## 3. 发第一个任务（推荐先发"只读"的）

1. 点 Run 卡片上的 **「详情」**，会展开一个面板。
2. 点展开面板里最上面那排的 **「＋ 发起任务」**。
3. 弹出一个输入框（"任务说明 prompt"），**粘贴下面这句话**再点确定：

   ```
   只读任务：请只回答你自己的名字和你能做什么，一句话即可，不要调用任何工具、不要修改任何文件。回答必须以 ANSWER= 开头。
   ```

4. **重点**：紧接着会弹出第二个提示 **「写任务？确定=写，取消=只读」**——
   - 想让 AI **只回答问题**：点 **「取消」**（取消=只读，别点错，这就是设计）
   - 想让它**真的改代码**：见文末第 6 节
5. 弹出绿色提示"任务已发起"后，点面板里的 **「刷新」**，看到表格里出现一行 `task-xxxx`。

---

## 4. 看它干完活

什么都不用做，盯着面板，大约 10~60 秒：

1. 任务那行的状态会变：紫色「就绪」→ 绿色「运行中」→ 绿色「已完成」。
2. 往下滚，在 **「事件时间线（最近 40）」** 里能看到每一步发生了什么（派给谁、在跑、完成……），越靠上越新。
3. 想让它干多个活就多「发起任务」几次，调度器会自动分给空闲的 AI，表格里能同时看到好几个在跑。
4. 想立刻知道有没有新变化：点「刷新」，或者干脆等 8 秒（页面会自动刷新列表）。

> 第一次跑通到这里就成功了。**你已经在用 Codex/CodeBuddy 当"外包团队"了。**

---

## 5. 控制按钮（每个都是字面意思）

展开 Run 详情后，面板顶部那排按钮：

| 按钮 | 作用 | 什么时候用 |
|---|---|---|
| ＋ 发起任务 | 派新活 | 想让它做事 |
| 暂停调度 | 暂时不派新活（在跑的不打断） | 想歇会儿 |
| 恢复调度 | 重新开始派活 | 暂停之后 |
| 刷新 | 手动看最新状态 | 等不及自动刷新 |
| 停止 serve（在卡片上） | 关掉调度器 | 今天不用了 |

另外任务表格每行最右有 **「取消」** 按钮：活派错了/不想让它干了就点它。

**收工**：点卡片上红色的 **「停止 serve」**，再关掉黑色终端窗口即可。数据都存在本地数据库里，下次启动还能看到这个 Run 的历史。

---

## 6. 想让它真的改代码（写任务）——目前网页版还没这个按钮

实话实说：写任务需要两个东西——**受管工作区路径（cwd）+ 允许改哪些文件（write_scope）**，还要你在它写完后来审核。这三个动作网页版还没做成按钮，所以我暂时不推荐你在网页上点"写任务"（你点确定=写 的话，因为没有工作区范围会被系统拒绝）。

**下一步我来补**（网页版加三样东西就能闭环）：
1. 发起任务时能填"要改哪些文件"（scope）；
2. 自动给每个 Run 准备一个受管工作区；
3. 工人干完停在「待审核」时，网页上有**通过 / 打回**按钮，通过后自动合并代码。

在那之前如果你急着用写任务，告诉我，我先把命令行版的一键写任务脚本给你；或者我直接把这三点做成 UI（推荐）。

## FAQ：卡住了看这里

**Q：浏览器打开是 Steam 页面？**
A：Steam 占了 8080。用黑色终端窗口里 `console listening on` 那行的地址访问；`start.cmd` 每次会自动挑空闲端口。

**Q：任务一直停在「就绪 / 待审核」不动？**
A：90% 是「serve 未启动」（看卡片右上角是不是灰的，先点「启动 serve」）；10% 是相关厂商没登录（去「厂商连接」看）。

**Q：任务变成红色「失败」/「阻塞」？**
A：最常见的两种：① 该后端没登录（去厂商连接确认）；② 只读任务别担心，多半是 AI 网络/超时，点「取消」后再发一次。想看具体原因，去事件时间线找 `task.failed` 那行，后面的文字会说明。

**Q：CodeBuddy 老提示没登录但明明登录过？**
A：网页控制台是用你自己的终端进程跑起来的。如果你是在别的地方（比如浏览器里的 WorkBuddy）登录的，**不会**自动共享。按第 1 节在 PowerShell 里跑一次 codebuddy `/login` 即可，之后一直有效。
